# 语义配置合并器

面向平台团队的本地 Web 应用：对同一份服务配置的**共同祖先 + 两个分支**做语义三方合并，
区分自动合并项与真实冲突，保留每个值的来源链，并支持可重放的人工裁决。

## 运行

```bash
./gradlew test
./gradlew run --args='--host 127.0.0.1 --port 5221'
```

打开 http://127.0.0.1:5221 即可看到「语义配置合并器」。无需任何外部进程，
数据持久化在 `./data/`（会话、裁决历史、输出），删除即可重置。

## 语义规则

- **对象**按键名三方合并；**数组**必须按路径登记策略，未登记一律报冲突，绝不猜测：
  - `REPLACE`：整体视为一个值；
  - `BY_ID`：按稳定 id 合并元素（重复 id / 缺 id 直接冲突），顺序做三方比较；
  - `SEQUENCE`：有序序列，纯重排可自动合并，两侧不同重排冲突。
- **删除 ≠ null ≠ 缺失**：三者各有独立指纹，删除与修改冲突为 `delete-vs-modify`。
- YAML 锚点/别名（含 `<<` 合并键）展开后参与比较，展开副本带 `alias-expanded`
  溯源标记；输出物化为独立节点，不产生共享可变引用。
- **人工裁决**绑定祖先与两侧的内容指纹（SHA-256）：指纹完全匹配才自动重放，
  任一侧变化后旧裁决降级为「建议」展示。
- 批量提交裁决使用**乐观版本**：`expectedVersion` 不匹配返回 409，
  过期页面无法覆盖他人已解决的项。
- 导出（YAML/JSON）附带每个结果路径的来源链与指纹清单；再导入时逐条校验，
  路径、来源链与结果指纹保持一致。

## 界面

三栏结构：左为合并结果结构树（一致/自动/冲突标记），中为节点详情
（来源链、冲突原因、三侧内容、逐项裁决按钮），右为导出文本预览。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sessions` | 创建合并会话（base/ours/theirs + 策略） |
| GET | `/api/sessions/{id}` | 会话状态（版本、自动项、冲突） |
| GET | `/api/sessions/{id}/tree` | 结构树 |
| GET | `/api/sessions/{id}/node?path=` | 节点详情 |
| POST | `/api/sessions/{id}/resolve` | 批量裁决（乐观版本） |
| GET | `/api/sessions/{id}/export?fmt=` | 导出文本 + 溯源清单 |
| POST | `/api/import` | 导入校验（路径/指纹一致性） |

## 测试

`./gradlew test` 覆盖：删除与 null、缺失字段、三种数组策略、重复 id、
未登记策略拒绝猜测、顺序移动、别名展开、旧裁决失效、并发裁决乐观版本、
稳定序列化与导出导入往返、持久化重载、YAML/JSON 指纹一致性。
