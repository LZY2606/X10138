# 语义配置合并器（Semantic Config Merger）

一个本地运行的 Kotlin Web 应用，对同一份服务配置的 **共同祖先（base）/ 分支 A / 分支 B**
做语义化三向合并，支持 YAML 与 JSON。它不做简单文本 diff，也不做“静默覆盖”的深合并：
每个结果值都带来源链，真正的冲突逐项交人工裁决，裁决可重放。

## 运行

需要 JDK 17（仓库已自带 Gradle Wrapper，无需系统 Gradle 或其它外部进程）。

```bash
./gradlew classes                     # 交付前编译检查
./gradlew test                        # 全部测试
./gradlew run --args='--host 127.0.0.1 --port 5221'
```

打开 <http://127.0.0.1:5221>，页面标题为「语义配置合并器」。

可选参数：`--host`、`--port`、`--data <目录>`（默认 `./data`，持久化目录）。

## 核心语义

- **对象按键名合并**；**数组必须先登记路径策略**，未登记且两边都改动时该路径被标记为
  `NO_STRATEGY` 并阻塞导出，系统不猜测。
  - `REPLACE`：整体替换，两边不同则二选一。
  - `ID`：按稳定 id 对齐元素（默认字段 `id`，可配置；支持字符串/数字 id），逐项三方合并；
    同 id 在两侧被移到不同位置产生 `ARRAY_ORDER`；单侧出现重复 id 产生 `DUP_ID`。
  - `SEQUENCE`：有序序列，使用 diff3 对齐；同一区域两边各自不同改动产生 `SEQUENCE_REGION`。
- **删除 / 显式 null / 缺失是三件不同的事**：
  - 删除：YAML 用 `!delete` 标签，或两种格式都可用对象 `{"$delete": true}`；
  - 显式 null：键存在且值为 `null`；
  - 缺失：键不存在，表示该方“无意见”，不与删除混淆。
  - 一边删除、另一边把同一路径设为 null 时产生 `DELETE_NULL` 冲突。
- **锚点/别名**参与比较前会展开为彼此独立的副本，输出绝不产生共享可变引用或 `*anchor`，
  节点详情会显示其来自哪个锚点/别名。
- **人工裁决绑定三方内容指纹**（base/A/B 的 SHA-256）。任一边变化后旧裁决不再自动套用，
  只以“建议”形式展示（`advisory`）。
- **乐观并发**：一次可提交多个冲突的裁决，请求带 `baseVersion`；版本过期或其中某项已被他人
  解决时整批拒绝（HTTP 409），后到者不能覆盖先解决者。

## 界面

三栏结构视图并排展示 base / A / B（合并树的同一路径），点选节点后右栏显示三方值、值类型、
锚点、来源链、自动合并说明或冲突原因与可选项，可逐项裁决或填写自定义结果文本。
右栏另有「导出预览」（切换 YAML/JSON、结果指纹、下载合并包、导入合并包）与「裁决历史」。

## 持久化与可重放

`data/<会话id>/session.json` 保存三份原始输入、解析指纹、策略版本、裁决列表与最近结果指纹；
`history.log` 追加记录每条裁决（审计）。

导出的 `.json` 合并包包含原始输入、策略、裁决、结果文本、结果指纹与路径集合。
导入时重新解析三份原始输入并重放合并，校验 **路径集合** 与 **结果指纹** 完全一致，
否则拒绝导入，保证「导出再导入」语义可重放。

## 内容指纹

`Canonical` 用带类型前缀的规范化表示计算 SHA-256：对象键按字典序（与书写顺序无关），
数组保序，数字按数值规范化（`1e2` 与 `100` 同指纹），缺失/null/删除使用不同标记不会串值。

## 测试覆盖

`./gradlew test` 覆盖：

- 删除 vs 显式 null vs 缺失；
- 数组三种策略（REPLACE / ID / SEQUENCE）；
- 重复稳定 id；
- 顺序移动（单侧移动自动合并、双侧不同移动冲突、裁决后按所选顺序物化）；
- 别名展开与无共享引用、重复键拒绝；
- 旧裁决因指纹失配而失效、仅作建议；
- 并发裁决的乐观版本与“不能覆盖已解决项”；
- 稳定/字节确定的序列化与导出再导入的路径、来源链、结果指纹一致性。
